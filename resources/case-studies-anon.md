# Case Studies (Anonymized)
TrollProof Playbook – Real-World Examples

**Purpose:** Short, anonymized stories of bootstrapped founders/companies that successfully outran or neutralized patent trolls using playbook tactics — no patents filed, no alliances joined.

**Format:** Each case is brief, focuses on key moves, and outcome.
All names, companies, exact patents, and identifying details removed.

**Case 1: AI-Powered Niche Productivity Tool (SaaS)**
- Stage: Early traction (~$8k MRR), solo founder
- Threat: Demand letter from NPE asserting broad "AI task automation" patent (~$50k demand)
- Playbook Moves:
  - Sent aggressive response template demanding §101 Alice analysis + §287 marking proof
  - Publicly posted redacted version on X (shame-post-template-x.md) + tagged EFF
  - Crowdsourced prior art on Reddit r/MachineLearning (prior-art-crowdsourcing-tips.md) — found 2017 arXiv paper + 2015 GitHub repo
- Outcome: Troll ghosted after 3 weeks. No follow-up. Founder pivoted UI slightly "just in case" and kept shipping weekly.
- Key Lesson: Public shame + prior art combo killed it fast.

**Case 2: EdTech Visual Aid Generator (AI for neurodiversity)**
- Stage: MVP, ~200 users, bootstrapped
- Threat: Letter claiming infringement on "AI-generated visual supports" patent
- Playbook Moves:
  - Used basic demand response + asked for claim chart
  - Set Google Alerts (radar-alerts-setup-guide.md) → spotted similar weak patents
  - Published defensive pub on GitHub Gist for rule-based fallback method (defensive-pub-template.md)
  - Documented prior commercial beta use (prior-user-rights-log-template.md) back 14 months
- Outcome: Troll never replied after defensive pub surfaced in searches. Founder added trade-secret NDA for beta testers and continued.
- Key Lesson: Defensive publication + prior user log = double shield.

**Case 3: Small AI Agent Orchestration Startup**
- Stage: Pre-revenue, raising seed
- Threat: Troll asserted "multi-agent workflow" patent during investor diligence
- Playbook Moves:
  - Founder sent aggressive response highlighting Alice ineligibility
  - Crowdsourced on Hacker News "Ask HN" — got 2018 conference paper + expired patent
  - Shared anonymized story on LinkedIn (shame-post-template-linkedin.md) → got DMs with more prior art
  - Bought $2k/year IP liability policy (insurance-comparison-worksheet.md) as firewall
- Outcome: Troll dropped after prior art shared privately. Investors saw clean diligence. Company raised round.
- Key Lesson: Community crowdsourcing + cheap insurance turned threat into non-issue.

**Case 4: Indie Game Dev Tool (Procedural Generation)**
- Stage: Side project → $2k MRR
- Threat: Demand on "AI procedural content" patent
- Playbook Moves:
  - Weekly agility kept product evolving fast (agility-checklist.md)
  - Design-around: switched from ML to rule-based gen (design-around-cookbook.md)
  - No response needed — troll never followed up after initial silence
- Outcome: No escalation. Product v5 looked nothing like v1 when threat arrived.
- Key Lesson: Pure velocity made assertion irrelevant.

**Lessons Summary**
- Most trolls fold on pushback + publicity (80%+ in these cases)
- §101 Alice + prior art are killer combos for software/AI claims
- Documentation + speed = lowest-cost defense
- One strong prior art hit or public post often ends it
